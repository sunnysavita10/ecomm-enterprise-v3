# Terraform deployment (staging template, not production-certified)
This creates a two-AZ VPC, private EKS worker nodes, ECR, encrypted RDS PostgreSQL, ElastiCache Redis, and private S3 catalog bucket. **It incurs AWS charges.**

Run `terraform init`, `terraform fmt -check`, `terraform validate`, then inspect `terraform plan -out=tfplan`; apply only after security and cost review. A remote encrypted S3 state backend with DynamoDB-compatible locking or S3 lockfiles must be configured by the operator before team deployment. Do not store state in git.

Before production: restrict EKS public endpoint CIDRs, review networking and ingress authorization, provision ingress/TLS/WAF/DNS and metrics-server, configure pod identity and Secrets Manager access, enable network policies, audits, alerting, backups/restores, multi-AZ NAT, node autoscaler, AWS budgets, and key rotation. RDS master secret is generated by AWS; the application credentials must be provisioned via your reviewed secret injection process. ElastiCache requires TLS; use `rediss://` and verify certificate support.

Infrastructure is *not* applied or verified in an AWS account.
